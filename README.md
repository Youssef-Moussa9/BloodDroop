# BloodDrop — منصة ربط متبرعين الدم بالمحتاجين

موقع متعدد اللغات (RTL/LTR) بيخلي المتبرع بالدم يسجل بياناته، والمحتاج للدم يلاقي أقرب متبرعين مطابقين لفصيلة دمه، مرتبين من الأقرب للأبعد (نفس المدينة → نفس المحافظة → نفس الدولة).

## الملفات

| الملف | وظيفته |
|---|---|
| `index.html` | هيكل الصفحة الأساسي |
| `style.css` | التصميم بالكامل (يدعم الوضع الليلي + الاتجاه من اليمين لليسار تلقائيًا) |
| `i18n.js` | كل النصوص والترجمات + قايمة اللغات |
| `app.js` | كل منطق التطبيق (الشاشات، الفورم، الفلترة الجغرافية، المطابقة) |
| `firebase-config.js` | مفاتيح مشروع Firebase بتاعك (فاضية دلوقتي) |
| `robots.txt` / `sitemap.xml` | يساعدوا جوجل يكتشف ويفهرس الموقع (قسم "الظهور في نتائج البحث" تحت) |

بدون خطوة Firebase تحت، الموقع **بيشتغل في وضع تجريبي محلي**: البيانات بتتخزن في ذاكرة المتصفح بس وبتتمسح لما تعمل ريفريش، ومفيش مشاركة بين الأجهزة. لازم تعمل الخطوات دي عشان يبقى فعلي:

## الخطوة 1: اعمل قاعدة بيانات مجانية على Firebase (حوالي 10 دقايق)

1. روح [console.firebase.google.com](https://console.firebase.google.com) وسجل دخول بحساب Google.
2. اضغط **Add project** واديله اسم (مثلاً `qatra-blood`)، وكمّل الخطوات الافتراضية.
3. من القايمة على الشمال: **Build → Firestore Database → Create database**. اختار **Start in production mode** والمنطقة الأقرب ليك جغرافيًا.
4. بعد ما تتعمل، روح لتبويب **Rules** فوق، وامسح الموجود وحط ده بدل منه:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /donors/{email} {
      allow list: if true;
      allow get: if request.auth != null && request.auth.token.email == email;
      allow create: if !exists(/databases/$(database)/documents/donors/$(email));
      allow update, delete: if request.auth != null && request.auth.token.email == email;
    }
  }
}
```

**إزاي القواعد دي شغالة (عشان تفهم اللي بيحصل):** كل متبرع بياناته متخزنة تحت "مفتاح" هو الإيميل بتاعه نفسه. أي حد يقدر يسجل بيانات جديدة لأول مرة (`create`)، لكن التعديل أو الحذف (`update`/`delete`) مسموح بس لو الشخص أثبت إنه فعلاً صاحب الإيميل ده (عن طريق رابط الدخول اللي هيوصله على إيميله — شرح الخطوة دي تحت). ده بيمنع أي حد يعدل أو يمسح بيانات حد تاني حتى لو عرف إيميله. كمان لو حد حاول يسجل تاني بإيميل مسجل قبل كده، هيرفضله النظام ويقوله يدخل من "سجّلت قبل كده؟" بدل ما يسجل تاني.

**ملاحظة:** مفيش جدول (collection) لبيانات "المحتاج للدم" خالص — المحتاج بيدوّر بس، ونتيجة البحث بتتحسب لحظيًا من غير ما نخزن حاجة عنه. ده يوفر خصوصيته ويخليه يستخدم الموقع بسرعة من غير ما يحس إنه بيسجل حساب.

## الخطوة 2: فعّل "الدخول برابط الإيميل" (Email Link Sign-in)

الخطوة دي هي اللي بتخلي أي متبرع أو محتاج يقدر يرجع بعدين يشوف بياناته أو يعدلها أو يمسحها.

1. من القايمة على الشمال في Firebase: **Build → Authentication → Get started**.
2. من تبويب **Sign-in method**، دوس على **Email/Password**.
3. فعّل السويتش الأول (**Email/Password**)، وتحته هتلاقي سويتش تاني اسمه **Email link (passwordless sign-in)** — فعّله هو كمان، ودوس **Save**.
4. لسه في نفس الصفحة (Authentication)، روح لتبويب **Settings → Authorized domains**، ودوس **Add domain**، واكتب دومين موقعك بعد ما تعمل GitHub Pages (مثلاً `your-username.github.io`).

بعد الخطوتين دول، ارجع لصفحة **Project settings** (أيقونة الترس فوق) وسجل تطبيق ويب زي ما هو موضح تحت في "الخطوة 3"، وحط المفاتيح في `firebase-config.js`.

## الخطوة 3: سجّل تطبيق الويب وخد المفاتيح

1. من صفحة المشروع الرئيسية، اضغط أيقونة **</>** (Web app) عشان تسجل تطبيق ويب جديد. اديله اسم واضغط **Register app**.
2. هيطلعلك كود فيه object اسمه `firebaseConfig` — انسخ القيم واحطها في ملف `firebase-config.js` مكان `YOUR_API_KEY` وباقي القيم.

## الخطوة 4 (اختيارية بس متنصوح بيها): قصر مفاتيح Firebase على دومين موقعك بس

المفاتيح اللي في `firebase-config.js` مش "سر" خطير (زي ما شرحنا فوق، Firestore Rules هي اللي بتحمي البيانات فعليًا)، لكن تقدر تزود طبقة حماية إضافية بحيث المفاتيح دي متشتغلش غير من دومين موقعك بالظبط:

1. روح [console.cloud.google.com](https://console.cloud.google.com) وسجل بنفس حساب Google اللي عملت بيه مشروع Firebase.
2. من فوق، اتأكد إنك واقف على نفس مشروع Firebase بتاعك (اسمه هيبان في القايمة المنسدلة فوق).
3. من القايمة على الشمال: **APIs & Services → Credentials**.
4. هتلاقي مفتاح اسمه شبيه بـ "Browser key (auto created by Firebase)" — دوس عليه.
5. تحت **Application restrictions**، اختار **Websites**، ودوس **Add** واكتب دومين موقعك (مثلاً `your-username.github.io/*`).
6. دوس **Save**.

## الخطوة 5: ارفع المشروع على GitHub وفعّل GitHub Pages

1. اعمل مستودع (repository) جديد على [github.com](https://github.com/new).
2. ارفعله كل الملفات اللي في المجلد ده (اسحبهم في صفحة الرفع، أو استخدم git من التيرمينال).
3. من إعدادات المستودع: **Settings → Pages → Source: Deploy from a branch**، اختار `main` والمجلد `/ (root)`، واحفظ.
4. بعد دقيقة أو اتنين، الموقع هيبقى شغال على رابط شبيه بـ:
   `https://your-username.github.io/your-repo-name/`

الموقع بيشتغل على أي جهاز (آيفون، أندرويد، تابلت، ويندوز) لأنه صفحة ويب عادية — مش محتاج تنزيل تطبيق.

## حدود النسخة الحالية (وأفكار للتوسعة)

- **تعديل/حذف البيانات:** بيشتغل عن طريق "رابط دخول" بيوصل على الإيميل (Firebase Email Link). لو الرابط مش بيوصل أو بيديك خطأ "unauthorized domain"، ارجع للخطوة 2 وتأكد إنك ضايف دومين موقعك بالظبط (بما فيه `https://` من غيره) في Authorized domains.
- **المحتاج للدم مبيسجّلش بياناته خالص:** بيدخل بس فصيلة الدم ومكانه، وبيشوف نتيجة البحث لحظيًا. مفيش اسمه أو رقمه أو إيميله متخزن في أي حتة — هو اللي هيدخل يكلم المتبرع، مش العكس.
- **الترجمة:** جاهزة بالكامل بالإنجليزية والعربية. باقي اللغات (فرنساوي، إسباني، صيني...) ظاهرة في قايمة الاختيار لكن بترجع تلقائيًا للإنجليزي لحد ما تترجمها. افتح `i18n.js` وشوف التعليمات فوق — نسخ بلوك `en` وترجمته لغة جديدة بياخد وقت قليل.
- **بيانات الدول/المحافظات/المدن:** بتتحمل لحظيًا من مكتبة بيانات جغرافية حقيقية (كل الدول والمحافظات والمدن)، مع خيار "اكتبها بنفسك" لو مكانك مش موجود في القايمة.
- **حماية من السبام:** حاليًا أي حد يقدر يبعت بيانات وهمية (لتسجيل جديد). لو حبيت تضيف حماية، أسهل حل سريع هو تفعيل [Firebase App Check](https://firebase.google.com/docs/app-check) أو إضافة reCAPTCHA على الفورم.
- **رقم التليفون:** مفيش تحقق فعلي إن الرقم حقيقي — ده يحتاج خدمة SMS مدفوعة زي Twilio أو Firebase Phone Auth لو حبيت تضيفه بعدين.
- **شخص واحد = سجل واحد لكل دور:** لو حد سجّل بنفس الإيميل تاني كمتبرع، هيوصله رسالة إنه مسجّل قبل كده ولازم يدخل من "سجّلت قبل كده؟" عشان يعدّل بدل ما يسجّل نسخة تانية. ده مقصود، عشان يمنع تكرار البيانات.

## الظهور في نتائج البحث (SEO)

ضفت للموقع كل العناصر التقنية اللي بتساعد جوجل ومحركات البحث التانية تفهم إن الموقع ده عن التبرع بالدم، بعدة لغات: عنوان ووصف غنيين بالكلمات المهمة (بالعربي والإنجليزي والإسباني والفرنسي...)، وبيانات منظّمة (Schema.org)، وملفي `robots.txt` و `sitemap.xml` اللي بيساعدوا جوجل يكتشف ويفهرس الموقع بسرعة أكبر.

**خطوة لازم تعملها:** افتح الملفات `index.html` و `robots.txt` و `sitemap.xml` وغيّر `https://your-username.github.io/qatra-blood/` لرابط موقعك الحقيقي بعد ما ترفعه.

**معلومة مهمة وصريحة:** مفيش حد — ولا حتى جوجل نفسها — يقدر يضمنلك إنك تظهر في أول 3 صفحات بحث. العناصر اللي ضفتها بتدّي لجوجل "إشارات" صح تساعده يفهم ويفهرس الموقع، لكن الترتيب الفعلي في النتائج بيعتمد على حاجات تانية برّه إيدي الكود: عمر الدومين، عدد المواقع اللي بتعمل لينك لموقعك، كثافة المنافسة على نفس الكلمات (و"تبرع بالدم" كلمة منافس عليها مواقع كبيرة زي بنوك الدم الرسمية)، وتكرار الزيارات الحقيقية. أفضل خطوة إضافية ممكن تعملها دلوقتي: سجّل الموقع في [Google Search Console](https://search.google.com/search-console) (مجاني) بعد ما ترفعه — ده بيسرّع عملية الفهرسة ويورّيك إحصائيات حقيقية عن ظهورك في البحث.

## تجربة الموقع محليًا قبل الرفع

افتح `index.html` مباشرة في أي متصفح، أو شغّل سيرفر بسيط من داخل المجلد:

```
npx serve .
```
